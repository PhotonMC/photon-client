# Yerel davranış testlerini çalıştırma

Python 3.10+ standart kütüphanesi ve Java 25 JDK kullanılır; yeni Python paketi veya test framework'ü yok. Rust JSONL adaptörü `serde_json` geliştirme bağımlılığını kullanır; üretim kütüphanesi haricî bağımlılık kullanmaz. Java adaptörleri doğrudan sabitlenen Minecraft JAR'ındaki sınıfları çağırır. Beklenen sonuçlar Rust'tan veya test içinde yeniden yazılmış algoritmalardan üretilmez.

Depo kökünden:

```bash
python3 tools/behavior/run.py preflight
python3 tools/behavior/run.py capture
python3 tools/behavior/run.py verify
python3 tools/behavior/test_runner.py
```

- `preflight`: client ve ilgili JAR hash'lerini, Java/javac sürümünü kontrol eder. Oyun veya test çalıştırmaz.
- `capture`: senaryoları iki ayrı Java sürecinde çalıştırır, çıktıları karşılaştırır ve kararlı referansı kaydeder. Aynı kimlikteki kaydı değiştirmez; mevcut kayıt farklı/bozuksa başarısız olur.
- `verify`: kayıtlı referansı değiştirmeden iki yeni Java çalıştırmasıyla karşılaştırır. Önceden `capture` yapılmış olmalı.
- `compare --adapter /mutlak/yol/program`: aynı girdileri belirtilen executable'a verir ve kayıtlı Java sonucuyla karşılaştırır. Rust wire/timer/math/utf8/binary/NBT adaptörü mevcut; bu komut adaptör verilmediğinde **2** ile çıkar. Derleme ve karşılaştırma komutları [binary dilim belgesindedir](binary-parity.md).
- `test_runner.py`: yalnızca yanlış başarı, bozuk referans ve hatalı süreç davranışlarını denetleyen beş küçük sentetik altyapı testi. Java veya asset gerektirmez.

Tek aile seçmek için `--family wire`, `--family math`, `--family timer`, `--family utf8`, `--family binary` veya `--family nbt` kullanılır; seçenek tekrarlanabilir. Seçilmezse mevcut bütün aileler çalışır. Aile seçimi referans kimliğinin parçasıdır; örneğin `verify --family timer` öncesinde aynı seçimle `capture --family timer` çalıştırılmalıdır. `--runtime /yerel/runtime` alternatif client/`libs` dizinini, `--jdk-home /jdk/koku` Java araçlarını seçer. Bu yollar yalnızca okunur. Gerekli referanslar yoksa indirme yapılmaz.

## Sonuç ve çıkış kodları

| Sonuç | Kod | Anlam |
| --- | ---: | --- |
| `preflight_ready` | 0 | Girdi ön kontrolü geçti; davranış doğrulanmadı |
| `reference_ready`, `rust_status=not_compared` | 0 | Java referansı kararlı/kayıtla eşit; Rust karşılaştırılmadı |
| `parity_passed` | 0 | Yalnızca seçilen senaryolarda verilen adaptör Java çıktısıyla eşleşti |
| `failed` | 1 | Çalıştırma/derleme/format hatası veya davranış farkı |
| `blocked` | 2 | Eksik/yanlış referans, yanlış JDK, eksik capture veya adaptör |

Referans komutunun başarılı olması istemcinin eşitliğini göstermez. Seçili bir ailede adaptörün geçmesi de diğer bölümlerin geçtiği anlamına gelmez. Genel CI'a yerel referans veya capture yüklenmez.

## Dosyalar ve kimlik

İzlenen dosyalar: `tools/behavior/` çalıştırıcı ve özgün girdi üreticisi; `tests/behavior/java/` özgün Java çağrı adaptörleri; `tests/behavior/reference.json` sürüm ve gerekli artifact hash'leri. Runtime için yalnızca seçili ailenin JAR'ları kullanılır; assetler, GPU, sunucu ve decompile kaynak ağacı bu ilk testlerin ön koşulu değildir.

Her koşu `.data/runs/behavior/<komut>-<benzersiz>/` altında input, stdout/stderr, derlenen sınıflar, kimlik ve `report.json` tutar. Rapordaki `reproduce` komutu `invocation_cwd` dizininden yeniden çalıştırılabilir. Her capture `.data/captures/behavior/<kimlik>/` altında `inputs.jsonl`, `outputs.jsonl`, `manifest.json` tutar. Referans kimliği client/dependency hash'leri, Java ve javac sürüm çıktısı, OS/mimari, seçilen aileler, Java adaptör/çalıştırıcı kodu ve senaryo girdilerini kapsar. Girdi veya çıktı dosyasının bozulması hash denetimiyle reddedilir.

Kaynak, senaryo veya ortam değişirse yeni kimlik için açıkça `capture` çalıştırılır; eski kayıtlar korunur. Bu kayıtlar kriptografik imzalı güven zinciri değildir; yerel test girdilerini ve kazara değişiklikleri izler. Değişen baseline'ı otomatik kabul eden bir test koşusu yoktur.

## Adaptör protokolü

Executable, stdin'den UTF-8 JSONL alır; her girdi için aynı sırayla stdout'a tek JSON nesnesi döndürür. stdout'a log yazmaz; loglar stderr'e gider. Süre sınırı 60 saniyedir, hata veya eksik/bozuk çıktı başarı sayılmaz. Süreç shell üzerinden başlatılmaz; çalışma dizini ilgili yerel koşu dizinidir.

Her girdi `schema_version: 1`, `case_id`, `family`, `operation` ve operasyona özgü alanlar içerir. Her çıktı aynı `schema_version`/`case_id` ve bir `result` nesnesi içerir. İsteğe bağlı `diagnostics` nesnesi (örneğin Java exception sınıfı) karşılaştırılmaz; bütün `result` alanları tür ve değer açısından kesin karşılaştırılır. Liste/olay sırası korunur; JSON nesnesindeki alan yazım sırası önemli değildir. Eksik/fazla/tekrarlı/sırası değişmiş kayıt başarısızdır.

`wire` ailesi: `codec` alanı `varint` veya `varlong`; `write` girdisindeki `value` işaretli ondalık **string**, `read` girdisindeki `hex` küçük harfli bayt dizisidir. Yazma sonucunda `outcome`, `size`, `hex`, `decoded`, `consumed`, `remaining_hex`; okuma sonucunda `outcome`, `value` veya `error`, `consumed`, `remaining_hex` bulunur. `buffer_underflow` ve `too_big` Java'dan gözlenen hatanın dil bağımsız kategorileridir; sınıf adı yalnızca tanısal kayıttadır.

Wire corpus'u: 144 senaryo; işaretli min/max, 7 bit sınırları, negatif değerler, kesilmiş/fazla uzun/noncanonical kodlamalar ve kalan baytlar. Her `write` çağrısında orijinal decoder da çağrılır; bağımsız sentetik `read` girdileri ayrıca bulunur. UTF-8 ayrı ailede Java referansı olarak hazır; diğer P03 biçimleri henüz kapsanmıyor.

JSON protokolünü konuşan bir executable'ın programlama dili araç tarafından kanıtlanmaz. `examples/behavior_adapter.rs` mevcut gerçek Rust wire/timer/math adaptörüdür; rapor executable SHA-256'sını ve seçili kapsamı kaydeder. Altyapı denemelerinde kullanılan sentetik programlar oyun eşitlik kanıtı değildir.

## Sayısal ve zamanlayıcı protokolü

`math/vec2`: girdide `x`, `y` ve `steps` bulunur. Float girdiler 8 haneli küçük harfli IEEE-754 hex string'leridir. `steps` içindeki `normalize` vektör normalizasyonunu, `scale` ise aynı kayıttaki `factor` çarpanıyla ölçeklemeyi çağırır. `result.events`, başlangıçta ve her işlemden sonra `x`, `y`, `length`, `length_squared` bitlerini içerir.

`math/vec3`: girdide `x`, `y`, `z` ve `steps` bulunur. Float girdiler 16 haneli küçük harfli IEEE-754 hex string'leridir. `steps` içindeki `normalize` vektör normalizasyonunu, `scale` aynı kayıttaki `factor` çarpanıyla ölçeklemeyi, `reverse` Java Vec3.reverse() çağrısını, `multiply_vec3` ve `multiply_components` Java Vec3 multiply overload'larını, `horizontal` Java Vec3.horizontal() çağrısını, `add_vec3`/`subtract_vec3` `delta` Vec3 değerini, `add_scalar`/`subtract_scalar` `value` değerini, `add_components`/`subtract_components` ise `x`, `y`, `z` miktarlarını Java Vec3 overload'larına verir. `vector_to`, hedef Vec3 değerini `target` nesnesinden alıp Java `vectorTo` çağrısına; `cross`, ikinci Vec3 değerini `other` nesnesinden alıp Java `cross` çağrısına verir. `result.events`, başlangıçta ve her işlemden sonra `x`, `y`, `z`, `length`, `length_squared` bitlerini içerir.

`math/vec3_codec`: `mode: "decode"` için `values` alanındaki raw f64 bit listesi Java `Vec3.CODEC` sabit boyutlu liste yoluna verilir; tam üç öğede Vec3 snapshot'ı, kısa/boş listede hata, uzun listede ilk üç öğeden `partial` snapshot döner. `mode: "encode"` için `x`, `y`, `z` raw f64 bitleri x/y/z sırasındaki üç öğeli listeye çevrilir. JSON sayı türlerinin genel metin ayrıştırması bu operation'ın kapsamı değildir.

`math/chunkpos_distances`: signed decimal i32 `x`, `z`, `other_x`, `other_z` alanlarını alır; Java `ChunkPos.getChessboardDistance` ChunkPos ve koordinat overload'larını, `distanceSquared` ChunkPos ve packed long overload'larını çağırır. `result.value` içinde dört sonuç decimal string olarak `chessboard_chunk`, `chessboard_coordinates`, `distance_squared_chunk` ve `distance_squared_packed` alanlarında taşınır.

`math/chunkpos_validity`: signed decimal i32 `x` ve `z` alanlarını alır; Java `ChunkPos.isValid()` instance ve `isValid(int, int)` static yollarını çağırır. `result.value` içinde `instance` ve `static` boolean alanlarını taşır; static initialization için yalnızca bu oracle yolu vanilla bootstrap'ı başlatır ve JSONL stdout akışını korur.

`math/chunkpos_from_section_node`: 16 haneli lowercase unsigned hex `section_node` alanını raw SectionPos packed long olarak alır; Java `ChunkPos.fromSectionNode(long)` x/z alanlarını çıkarıp y'yi atar ve sonucu unsigned lowercase hex `result.value` olarak taşır.

`math/chunkpos_range_closed`: `mode: "from-to"` için signed decimal i32 `from_x`, `from_z`, `to_x`, `to_z`; `mode: "center-radius"` için signed decimal i32 `x`, `z`, `radius` alanlarını alır. Java `ChunkPos.rangeClosed` iki overload'undan oluşan inclusive x-fastest/z-next akışını tüketir; `result.value.positions` her ChunkPos'u decimal string x/z alanlarıyla taşır. Büyük overflow aralıkları bu operation senaryolarında kullanılmaz.

`math/chunkpos_constant`: `name` alanını `zero`, `invalid_chunk_pos`, `region_size` veya `region_max_index` olarak alır. Java `ChunkPos` public static sabitini doğrudan sorgular; `result.value` sırasıyla `chunk_pos` x/z decimal string alanını, `packed` unsigned lowercase hex packed long'u veya `value` decimal stringini taşır.

`math/chunkpos_packed_accessors`: 16 haneli lowercase unsigned hex `packed` alanını raw ChunkPos long olarak alır; Java `ChunkPos.getX(long)` ve `getZ(long)` düşük/yüksek 32 bit alanlarını signed i32 sonuçlara çevirir. `result.value.x` ve `result.value.z` decimal string alanlarıdır.

`math/sectionpos_packed_accessors`: 16 haneli lowercase unsigned hex `packed` alanını raw SectionPos long olarak alır; Java `SectionPos.x(long)`, `y(long)` ve `z(long)` 22/20/22 bit alanlarını signed i32 sonuçlara çevirir. `result.value.x`, `result.value.y` ve `result.value.z` decimal string alanlarıdır.

`math/sectionpos_block_coordinates`: signed decimal i32 `x`, `y`, `z` section koordinatlarını alır; Java `SectionPos.minBlockX/Y/Z` ve `maxBlockX/Y/Z` instance yardımcılarını çağırır. `result.value` içinde altı blok sınırı `min_block_x/y/z` ve `max_block_x/y/z` decimal string alanları olarak taşınır.

`math/sectionpos_relative_to_block`: signed decimal i32 section `x`, `y`, `z` ve signed decimal short `relative` alanlarını alır; Java `sectionRelativeX/Y/Z`, `relativeToBlockX/Y/Z` ve `relativeToBlockPos` yollarını çağırır. `result.value` içinde relative ofsetleri, blok x/y/z ve `block_position` snapshot'ı taşınır.

`math/sectionpos_spatial`: signed decimal i32 `x`, `y`, `z` section koordinatlarını alır; Java `SectionPos.origin()`, `center()` ve `chunk()` instance yardımcılarını çağırır. `result.value` içinde `origin`, `center` BlockPos ve `chunk` ChunkPos snapshot'ları taşınır.

`math/sectionpos_packed_transformations`: 16 haneli unsigned hex `block_node` ve `section_node` ile signed decimal i32 `x`, `z` alanlarını alır; Java `SectionPos.blockToSection`, iki `getZeroNode` overload'u ve `sectionToChunk` statik yollarını çağırır. `result.value` içinde dört packed sonucu unsigned lowercase hex string olarak taşır.

`math/sectionpos_as_long`: 16 haneli unsigned hex `block_node`, signed decimal i32 `x`, `y`, `z`, `section_x`, `section_y`, `section_z` alanlarını alır; Java `SectionPos.asLong(BlockPos)`, `asLong(int, int, int)` ve instance `asLong()` yollarını çağırır. `result.value` içinde `from_block_pos`, `coordinates` ve `instance` packed sonuçlarını unsigned lowercase hex string olarak taşır.

`math/sectionpos_offset`: 16 haneli unsigned hex `section_node`, küçük harfli `direction`, signed decimal i32 `step_x`, `step_y`, `step_z`, `x`, `y`, `z` alanlarını alır; Java `SectionPos.offset(long, Direction)`, `offset(long, int, int, int)` ve instance `offset(int, int, int)` yollarını çağırır. `result.value` içinde `packed_direction`, `packed_steps`, instance x/y/z ve instance packed sonucu taşır.

`math/sectionpos_ranges`: `mode: "between"` için signed decimal i32 `min_x`, `min_y`, `min_z`, `max_x`, `max_y`, `max_z`; `mode: "cube"` için `x`, `y`, `z`, `radius`; `mode: "around-chunk"` için `chunk_x`, `chunk_z`, `radius`, `min_section`, `max_section` alanlarını alır. Java `SectionPos.betweenClosedStream`, `cube` ve `aroundChunk` yollarını tüketir; `result.value.positions` x/y/z ve packed SectionPos snapshot'larını Java'nın x-fastest, y-next, z-next sırasıyla taşır. Senaryolarda büyük overflow aralıkları kullanılmaz.

`math/sectionpos_blocks_inside`: signed decimal i32 `x`, `y`, `z` section koordinatlarını alır. Java `SectionPos.blocksInside()` ve `BlockPos.betweenClosedStream` yollarını tüketir; `result.value.positions` içindeki 4096 BlockPos x/y/z snapshot'ı Java'nın x-fastest, y-next, z-next sırasını taşır.

`math/sectionpos_around_and_at_block_pos`: `mode: "coordinates"` için signed decimal i32 `x`, `y`, `z`; `mode: "blockpos"` için aynı alanlar; `mode: "packed"` için 16 haneli unsigned hex `block_node` alır. Java `SectionPos.aroundAndAtBlockPos` üç overload'unu callback ile tüketir; `result.value.section_nodes` packed SectionPos değerlerini sectionX dış, sectionY orta, sectionZ iç sırasıyla unsigned lowercase hex olarak taşır.

`math/sectionpos_double_coordinates`: `fn: "pos_to_section"` veya `"block_to_section"` ve 16 haneli unsigned hex f64 bit deseni olan `value` alanını alır. Java `SectionPos.posToSectionCoord(double)` veya `blockToSectionCoord(double)` overload'unu çağırır; `result.value` signed decimal i32 section koordinatıdır.

`math/sectionpos_of_overloads`: `mode` değeri `blockpos`, `chunkpos`, `position` veya `packed` olabilir. BlockPos/ChunkPos yolları signed decimal i32 alanları, `chunkpos` ayrıca `section_y`, `position` x/y/z için 16 haneli f64 bit string'leri, `packed` ise 16 haneli `section_node` alır. Java `SectionPos.of(...)` sonucu `result.value` altında x/y/z signed decimal ve packed unsigned lowercase hexadecimal snapshot olarak taşınır.

`math/mth_integer_helpers`: `type` değeri `i32` veya `i64`, `fn` değeri `floor_div`, `positive_modulo`, `positive_ceil_div` veya `round_toward` olabilir. `input` ve `divisor` signed decimal string'lerdir. Java `Mth`/`Math` tamsayı yolları doğrudan çağrılır; `result.value` signed decimal string olarak taşınır. Senaryolarda bölen sıfır değildir; Java integer overflow sonucu korunur.

`math/mth_integer_basics`: `type` değeri `i32` veya `i64`; `fn` değeri `abs`, `clamp`, `is_multiple` veya `wrap_degrees` olabilir. `input`, clamp için `min`/`max`, katlık için `divisor` signed decimal string'lerdir. Java `Mth` tamsayı yolları doğrudan çağrılır; `result.value` mutlak değer/clamp/sarmalama için signed decimal string, `is_multiple` için boolean taşır. Clamp sınırlarının sırası korunur ve katlık böleni sıfır değildir.

`math/mth_angle_helpers`: `type` değeri `f32`, `i8` veya `i64`, `fn` değeri `pack_degrees`, `unpack_degrees` veya `wrap_degrees` olabilir. Java `Mth` rounding yolları doğrudan çağrılır; `ceil` sonucu signed int, `lfloor` ve `ceil_long` sonuçları signed long decimal string olarak `result.value` içinde taşınır.

`math/mth_positive_modulo`: `type` değeri `f32` veya `f64` olabilir. `input` ve `mod` raw f32/f64 bit string'leridir. Java `Mth.positiveModulo` sonucu raw f32/f64 bit string olarak `result.bits` içinde taşınır.

`math/mth_abs_max`: `type` değeri `f32` veya `f64` olabilir. `first` ve `second` raw f32/f64 bit string'leridir. Java `Mth.absMax` sonucu raw f32/f64 bit string olarak `result.bits` içinde taşınır.

`math/mth_equal`: `type` değeri `f32` veya `f64` olabilir. `first` ve `second` raw f32/f64 bit string'leridir. Java `Mth.equal` sonucu boolean olarak `result.equal` içinde taşınır.
